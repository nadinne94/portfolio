Parlamentar

Pipeline de dados que acompanha, mês a mês, o que os deputados federais de Minas Gerais fazem na Câmara: proposições, votos nominais, presença em plenário e gastos da cota parlamentar.

Visão geral

Objetivo

Gerar, todo mês, um retrato da atuação de cada deputado da bancada mineira, a partir da API de Dados Abertos da Câmara. A página oficial organiza esses dados por ano; aqui o recorte é mensal.

Ponto de partida

Meu projeto anterior com dados da Câmara usava Databricks e outras ferramentas em período de teste. Quando os testes expiraram, o pipeline deixou de rodar. Este projeto nasceu com duas regras: custo zero permanente e execução completa na minha máquina com um único comando.

Como está sendo construído

Em incrementos verticais: cada um vai da API até o site publicado e termina numa versão com tag no Git. Nenhum incremento começa com o anterior pela metade, e dúvidas técnicas são resolvidas em spikes curtos antes do código de produção.

Práticas de engenharia

Testes desde o primeiro commit

Testes unitários com pytest, testes de ingestão contra respostas gravadas da API (sem depender da rede) e testes de dados no dbt para duplicatas e mapeamentos.

pytestdbt testsCassetes

CI/CD no GitHub Actions

Todo trabalho entra por pull request e passa por três verificações: qualidade, testes e transformação. Cada merge na main executa o pipeline e publica o site.

GitHub Actionspre-commitRuff

Decisões documentadas

Escopo, stack, contrato de dados e mudanças de rota ficam registrados em ADRs. As investigações sobre cada parte da API ficam em notas de spike.

ADRsSpikesRoadmap

Resiliente a uma API instável

A API da Câmara responde com erros 504 com frequência. O cliente HTTP repete as chamadas com espera crescente, e os dados brutos ficam guardados numa release do GitHub, então o site é publicado mesmo com a API fora do ar.

httpxtenacityParquet

Contrato canônico de dados

As fontes são convertidas para um modelo comum de fatos e dimensões, com contrato aplicado nos marts. Novas fontes entram sem mexer no resto do pipeline.

Modelagem dimensionaldbt contracts

Validação na entrada

Cada recurso da API tem um modelo Pydantic. Dado fora do formato esperado é barrado na ingestão, antes de chegar às tabelas analíticas.

Versões entregues

v0.0.1: Esqueleto andante

Estrutura do repositório, CI, projeto dbt, gerador de site e deploy. Um push na main já deixava a página publicada.

v0.1.0: Deputados de MG

Primeiros dados reais no site: a bancada mineira em exercício.

v0.2.0: Proposições

Proposições de cada mês na página de cada deputado, separando autoria de coautoria, e persistência dos dados brutos em release do GitHub.

Em andamento: votos nominais

Ingestão mensal das votações do Plenário e o voto de cada deputado. Depois vêm presença em plenário e gastos da cota parlamentar.

A meta é ter o pipeline operando sozinho em fevereiro de 2027, no início da nova legislatura, com o primeiro relatório mensal publicado em março.
